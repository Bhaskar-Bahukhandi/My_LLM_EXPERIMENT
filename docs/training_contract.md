# Bounded CPU training contract

The accepted 1,929,579-parameter architecture and CPU FP32 restriction are unchanged. No external corpus, optimizer framework or dependency is introduced. A manifest binds relative document identities, SHA-256, byte counts, split and domain; one file is one document. Source bytes are reverified before updates, validation and checkpointing. Windows are non-overlapping, never cross documents, retain short tails and begin a fresh BOS request. Batches group equal lengths without inserting PAD. Raw targets are 0..255; the existing model already performs causal shifting, so loss uses the supplied targets at the same indices. Normalization includes the unified admissible symbol head; byte NLL is summed over raw-byte targets only.

Training configuration fixes seed, sequence length (at most 256 in this tranche), microbatch size, accumulation count, total optimizer updates, AdamW hyperparameters, clipping, warmup/cosine schedule and CPU thread count. Each update divides microbatch summed NLL by the total valid targets across its accumulation window; unequal tails therefore receive correct byte weighting. Counters separate microbatches, optimizer updates, examples and raw bytes. Validation aggregates NLL sums/counts under eval/inference mode and restores the prior model mode.

AdamW groups each unique trainable identity once. Parameters tagged _no_weight_decay and all rank-zero/rank-one tensors have zero decay; remaining tensors have configured decay. No name substring policy is used. AdamW state is lazy: parameters unused by short tail windows have no state until their first gradient, and each parameter maintains its own update count. Checkpoints record the ordered per-parameter counts, require exactly the corresponding state coverage, and validate each scalar count against its tensor state and the global update bound. They do not manufacture gradients or optimizer state for unused parameters. Learning rate warms linearly to base LR, then cosine-decays to the configured minimum ratio; its index is the optimizer-update index, independent of microbatches.

Checkpoints are supported only at completed optimizer boundaries (accumulation position zero, gradients cleared). A failed update poisons that trainer instance; use the last complete checkpoint. Checkpoint state captures weights, optimizer, schedule, counters, Python/Torch CPU RNG, data permutation/cursor, both configs, manifest hash, parameter structure, code/environment and semantic metric history. Resume creates a new immutable run identity with a parent checkpoint, then restores state; incompatible semantics are rejected. Wall-clock measurements are observational and cannot be bit-identical across a restart; all semantic metric fields must match exactly.

Checkpoint publication writes and fsyncs state plus a SHA-256 manifest in a private sibling directory, verifies readability, then atomically renames the directory to a previously unused checkpoint identity. No existing run/checkpoint is overwritten. No mid-accumulation or GPU checkpoint completeness is claimed.

Predeclared tiny-overfit fixture: train is b"edge400: abcdef\n" repeated 64 times (1,024 bytes); validation is b"edge401: uvwxyz\n" repeated 16 times (256 bytes). They are different files/windows. Experiment: 32-byte windows, microbatch 2, accumulation 2, 60 optimizer updates, seed 17, LR 0.003, warmup 5, minimum LR ratio 0.1, weight decay 0.01 and clip norm 1.0. No fixture or success metric will be changed after seeing results to manufacture the planned 50% training-NLL reduction gate. Initial/final train NLL use the same entire training split; held-out NLL is separately reported and is not a generalization claim.

Generation uses the real incremental model with an explicitly bytes-only greedy policy for this raw-byte fixture. Tensor payload counts are separate from Windows working-set/RSS measurements. Autograd/activation storage is not inferred by subtracting tensor arithmetic from RSS. The quadratic SSD reference remains restricted to short windows; no 4096-byte training or GPU work occurs here.
