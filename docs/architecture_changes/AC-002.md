# AC-002 — SSM state accounting

- Change ID: AC-002.
- Current specification: Roadmap §12.16 uses B*layers*heads*d_state*element_bytes while §12.14 defines heads=d_inner/headdim.
- Observed issue: The state has a separate headdim axis; omitting it undercounts memory.
- Evidence that the issue is real: FACT: Bible §44 and the pinned upstream allocate [B,heads,headdim,d_state].
- Proposed replacement: Compute SSM state bytes from all axes, plus separate convolution state [B,d_inner+2*d_state,d_conv].
- Mathematical justification: FACT: Bible §44 and the pinned upstream allocate [B,heads,headdim,d_state].
- Primary sources: original Bible/Roadmap sections above; for upstream tensor layout see [pinned source](https://github.com/state-spaces/mamba/blob/d7b1ceb3c367ec9022925e812f507bcf706937c6/mamba_ssm/modules/mamba2.py).
- Implementation impact: Compute SSM state bytes from all axes, plus separate convolution state [B,d_inner+2*d_state,d_conv].
- Parameter impact: no new trainable capability; accounting distinguishes capacity and representation.
- Memory impact: declared payload/state accounting only; process-memory changes unmeasured.
- Training impact: no training implemented; affected gates must pass before training.
- Inference impact: no inference implemented; causal semantics cannot be relaxed.
- Backward compatibility: original FINAL specifications remain byte-identical; no prior model/checkpoint exists.
- Affected tests: configuration, structural inventory and memory accounting; routing tests deferred with MoE.
- Required new tests: Compare derived bytes with allocated metadata tensor numel*element_size over several legal shapes.
- Risks: incorrect adoption could conceal a causal or accounting bug; numerical execution remains unverified.
- Alternative approaches considered: retain ambiguous formula literally (rejected where contradicted by arithmetic); defer all dependent accounting (unnecessary once correction is documented).
- Rollback procedure: retain the original FINAL specifications and versioned inventory; revert the correction-dependent code/metadata as a unit, mark accounting unverified, and prohibit promotion. Never reinstate a known incorrect formula as validated.
- Decision: Accepted mathematical correction for preliminary accounting; no claim of measured runtime RSS.

MEASURED RESULT: none asserted by this proposal. HYPOTHESIS: downstream quality/performance benefits are untested. ENGINEERING PREFERENCE: keep corrections isolated and preserve specification history. Test outcomes belong in the tranche report.
