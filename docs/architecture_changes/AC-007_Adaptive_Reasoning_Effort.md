# AC-007 — Adaptive Reasoning Effort

Version 1.0 • 2026-09-22 • **PROPOSED / RESEARCH CONTRACT — NOT IMPLEMENTED OR ENABLED**

## Existing design and new contract

The [Bible](../../Unified_Edge400_Master_Bible_v3.0_FINAL.md) §165 already defines optional weight-tied residual latent refinement, fixed K=1/2/4/8 research, later adaptive halting, task-level use and no-regression gates. [Roadmap](../../Unified_Edge400_Master_Roadmap_and_Formula_Board_v1.0_FINAL.md) W45–W46 and §27 retain those equations and experiments. This proposal neither replaces the recurrence nor introduces a different latent architecture.

New: a user/system-facing **Auto, Low, Medium, High, Ultra** effort contract that jointly budgets eligible optional subsystems. Effort changes COMPUTE BUDGET, not a requirement to reveal private hidden reasoning or chain-of-thought. The [addendum](../../Unified_Edge400_Future_Capabilities_Addendum_v1.0.md) owns the integrated boundary; AC-006 owns succession and AC-008 owns context/distribution evidence.

## Resolved effort policy

Labels select a versioned host policy for a specific model generation and supported profile. They are not universal K assignments: **Low=K1 / Medium=K2 / High=K4 / Ultra=K8 is not a permanent mapping**. Resolution must precede execution and record requested label, resolved policy ID/hash, generation, supported features, hard resource envelope, seed where applicable and fallback/termination behavior. An unsupported label/profile must return an explicit unsupported result or a disclosed preauthorized fallback, never silently enable a subsystem.

Each level, including Auto, has finite declared maxima for all applicable axes:

| Axis | Accounting / enforcement |
|---|---|
| Latent refinement | Iterations and eligible task-level decision points; no unconditional per-byte refinement |
| Retrieval | Calls, documents, depth/hops and injected bytes |
| Reranking | Candidate set size and compute |
| Verification | Passes and executable test budget |
| Tools | Calls, retries and broker permissions; effort never grants permissions |
| Repair | Revision attempts including failed or repeated candidates |
| Candidate generation | Count and total generated bytes |
| Self-consistency | Optional sample count and aggregate cost; not mandatory |
| Wall clock | End-to-end deadline covering model, retrieval, tools and revision |
| Memory | Host/device ceilings and permitted concurrency |
| Output | Byte ceiling; tokens only with an explicitly identified tokenizer/conversion unit |

A host-approved policy must resolve these maxima before activation; this proposal supplies no unverified numerical thresholds. Shared end-to-end ceilings constrain the sum of subsystem work. Nested tools, retries and candidate fan-out cannot reset the request budget. Record consumed resources, decisions, observations and stop reason without private reasoning transcripts. High/Ultra permit more approved compute where supported; they promise neither more correct answers nor longer output. Per-generation evaluation decides useful allocations and ordering.

## Base/off compatibility

Every experimental subsystem is independently disableable. Off is the compatibility path, not a sixth effort label. If reasoning functionality is disabled, dispatch to the accepted base path and preserve its output/state/RNG behavior bit-identically on the deterministic same-profile reference, or under an explicitly declared, preapproved numerical tolerance for a named alternate backend. Record the tolerance before results; do not widen it to conceal a regression. No optional controller may consume hidden RNG or mutate base state in off mode.

A failure may terminate explicitly or use a preauthorized clean base branch; partial tool results, altered state or failed evidence must not leak silently into that fallback. The current dense 2M path has no new effort interface and remains unchanged. Enabling labels without a trained, tested optional branch is not a capability upgrade.

## Auto effort controller

Auto is a budget controller, not a separate model. Observable inputs may include task class, request complexity, verifier confidence, retrieval confidence, tool failure, uncertainty/entropy, contradiction detection, prior repair failure and remaining time/resources. These signals are fallible; neither entropy nor latent convergence proves correctness.

The host selects or escalates among preauthorized actions only inside the initial envelope. Record trigger, chosen action, remaining budget and stop reason. Reaching a cap ends work or returns an explicit unresolved result. Auto cannot recursively increase its own allowance; the candidate cannot change policy, permissions or accounting. Deadline enforcement belongs outside model cooperation. Future research must compare fixed policies against Auto at matched total budgets and report both accuracy and tail latency.

## Contradiction-aware host correction

```text
draft answer
  -> retrieve/tool/execute/verify evidence
  -> compare claims with provenance-bearing evidence
       -> no material contradiction: continue/finalize within scope
       -> material contradiction: bounded revision -> reverify
            -> final response or explicit unresolved state at deadline/attempt cap
```

This extends existing host repair (Bible §§24–30, 88–92), rather than reimplementing it inside neural forward. The host records draft/revision identities, contradicted claim, source/version/hash, evidence reliability and scope, correction action, verification outcome and resource consumption. Absence of a detected contradiction is not proof of truth. Conflicting, stale or low-confidence sources may remain unresolved; the controller must not fabricate evidence or silently relabel an unrun check as PASS. Retrieved instructions remain untrusted data (Bible §104).

**self-correction != self-training != self-modification != recursive self-improvement**:

- Self-correction revises the current answer/artifact using evidence; no weight or source changes.
- Self-training updates weights under a separately authorized training recipe.
- Self-modification changes code/configuration under a separately authorized experiment.
- RSI is externally evaluated and promoted parent/child succession under AC-006, not merely a repair loop.

## Impact, future gates and rollback

Current neural parameters, memory, weights, data, training, inference semantics and checkpoint format: unchanged. Future controllers incur measurable host overhead; latent branches retain Bible §165 audits, and all optional resource costs enter the resolved envelope. No runtime schema or effort implementation is added.

Required future evidence: off-path equivalence (outputs, states, RNG and failure cases), fixed-K ablations before adaptive halting, effort-policy calibration per generation, bounded Auto escalation including nested retries, timeout/OOM/tool failures, contradiction detection with adversarial/stale evidence, unresolved termination, and quality/latency/memory non-regression. Avoid replacing the current greedy Stage-A policy to make its samples look better.

Rejected alternatives: permanent label-to-K binding; exposing hidden reasoning; unlimited escalation; pretending every effort level guarantees quality. Rollback disables the optional policy and selects the retained base checkpoint/system bundle; it cannot undo external tool side effects, so the tool broker must separately authorize and contain them. Decision: pending human review, all effort functionality remains research-only.
