# Windows CUDA FP32 execution contract

This extends runtime placement of the accepted generic PyTorch model; its equations, parameter names/shapes, resolved architecture and state schemas are unchanged. The resolved inventory hardware remains the historical CPU lower-bound planning profile. Actual execution placement is explicit in TrainingConfig.device (cpu or cuda:0), run/checkpoint environment and measured CUDA evidence; inventory metadata is not a claim of GPU fit. Model construction initializes on CPU and moves once at the system boundary before optimizer construction. States, masks and temporary recurrence tensors derive their device from owning weights or inputs. No mixed precision or optimized Mamba kernels.

The CPU environment .venv remains unchanged. A separate .venv-cuda uses official PyTorch 2.6.0+cu118, preserving the API version. CUDA 11.8 is the oldest offered official 2.6.0 Windows CUDA wheel and is sufficient for compute capability 8.6; the observed 596.21 driver supports older CUDA applications. Installation identity and actual execution, rather than driver visibility alone, determine success. Dependencies remain pinned separately in requirements-cuda-lock.txt.

Predeclared FP32 parity gate: atol=1e-5, rtol=1e-4 for CPU/CUDA and independent full/step outputs and states. Report max absolute error and max relative error using denominator max(abs(reference), 1e-12); the combined tolerance, not relative maximum alone, is the gate. Seeds 17 and 29, batches 1 and 2, all requested short/patch-boundary lengths through 129, and adversarial suffix boundaries through 129 are exercised. No tolerance adjustment without recorded evidence.

CUDA deterministic execution disables TF32 and cuDNN benchmarking, enables deterministic algorithms/cuDNN, and requires CUBLAS_WORKSPACE_CONFIG=:4096:8 before CUDA initialization. One visible CUDA device is the bounded supported training profile. The CPU reference remains separately validated in .venv; CPU model forward also participates in the CUDA-wheel parity tests. CUDA RNG states are captured/restored alongside CPU/Python RNG and cursor. Training checkpoint schema 2 adds CUDA RNG state; the integrity-manifest schema remains 1 and model snapshot schema remains 1. Earlier schema-1 training checkpoints require the approved CPU rollback source/environment; no silent migration or cross-device resume claim.

Memory evidence synchronizes CUDA and records allocated, reserved, peak allocated/reserved plus free/total device memory at each named stage. These allocator counts are distinct from total GPU/process use. Fit probes use separate model instances and fixed requested configurations in one process and a conservative 1 GiB allocator budget, leaving at least 1 GiB observed free-device headroom for a recommended profile. A preflight rejection is BLOCKED, not an observed OOM. Actual CUDA OOM is DOES_NOT_FIT with stage recorded; no adaptive resizing. Larger candidates use the existing resolver, FP32, batch 1 and sequence 32 for one optimizer update only. This does not establish full-training capacity. Allocator measurements include process-global library workspaces and any live allocations at the recorded before-model stage; they are not isolated per-model payloads. No subtraction is used to present them as such.

The baseline short-learning gate uses the unchanged controlled fixture, 32-byte windows, batch 2, accumulation 2, seed 17, 10 optimizer updates, warmup 2 and the accepted AdamW hyperparameters. Initial/final whole-training-split NLL must decrease; held-out NLL is separate. Same-device resume compares six continuous updates with three-save-destroy/recreate-three and requires exact semantic equality when the configured deterministic kernels permit it. Mixed precision, real-data acquisition, WSL, custom kernels and later substantive training remain outside this tranche.

Sources: [official PyTorch 2.6.0 wheels](https://pytorch.org/get-started/previous-versions/#v260), [NVIDIA CUDA compatibility](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html).
